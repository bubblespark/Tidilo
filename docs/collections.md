# Manual Collections

Collections are user-curated groups, independent of AI taxonomy, bookmark origin, and Like. An active bookmark may belong to several collections, including collections containing both manual and RSS bookmarks. All collection content stays in the local Room database.

## Persistence and lifecycle

Room version 16 adds `collections` and `bookmark_collection_cross_ref` through the non-destructive `MIGRATION_15_16`. Existing bookmark, trash, RSS, queue, notification, and engagement data is preserved.

`CollectionEntity` stores UUID String `id`, `title`, `description`, nullable `presetIconId` and `customSymbol`, `colorIndex`, `createdAt`, and `updatedAt`. The membership table has a composite `(bookmarkId, collectionId)` primary key, individual indices on both columns, and cascading foreign keys. Bookmark IDs remain Strings, matching existing bookmark identity.

CollectionDao returns aggregate counts through Flow and collection bookmarks through PagingSource. CollectionRepository validates writes and saves each membership change atomically. Empty collections remain visible. Counts and pages apply the same Private Content visibility rule and include all bookmark sources. Collections and their bookmarks sort by creation time descending, then ID descending. Membership changes do not change collection creation order.

Collection membership exempts RSS articles from automatic age deletion while any membership remains. Removing the last membership resumes the normal age rule without restarting its clock; a Like still protects the article. Image cache remains disposable under [Daily Library Maintenance](library_maintenance.md).

Normal bookmark upserts preserve memberships. Explicit URL replacement transfers the affected memberships to the surviving bookmark ID within the existing write transaction. Failed replacement or membership writes roll back completely. A collection deleted while being edited cannot be recreated by autosave.

Deleting a collection removes its memberships and keeps every bookmark. Moving a bookmark to trash removes all memberships and stores `isLiked = false` in its trash snapshot. Unrelated engagement counters and timestamps remain intact. Collection or Like restoration is outside this feature.

## Library and editing

The Library filter menu includes Collection. Its single-column list uses the `prototype/collection-library` design: two background card layers, bold ellipsized heading, two description lines, count pill, gradient, and unframed icon/symbol watermark. Empty collections still have cards. The footer's dashed add card opens New Collection. With the Discover preview on, the Collection tab with no collections shows an explanation and a **New collection** button instead of the dashed card, and the cards use the Library layer's tonal layers ([Library UI §9](ui_library.md#9-library-layer-discover-preview)). Long press gives haptic feedback and opens Edit Collection. Tap opens the collection's paged bookmark list, with the existing list/grid switch and back behavior.

Collection cards and the add card expose button roles to accessibility services. Count pills use an opaque accent-tinted surface with `onSurface` content for legibility across all eight accents in light, dark, and dynamic themes. The list subtitle uses quantity-aware singular/plural collection counts. Card gradients and dashed-border drawing objects are cached.

Card bookmark counts also use English singular/plural quantities and retain the existing Japanese count format. The Collection filter exposes its button role and selected state. Preset icons and palette colors form separate single-choice groups with radio roles; a custom symbol leaves the preset group unselected.

The selected collection ID is saved separately from its latest Room metadata. Editing a title or color updates presentation without changing identity. Collection ID and Private Content visibility participate in the Paging session key; outgoing sessions retain their existing leases, and same-key database invalidation keeps loaded bookmarks mounted. Deleting the selected collection returns to the collection list.

The editor uses a scrollable Material 3 modal bottom sheet with IME and navigation-bar padding. Creating a collection keeps an explicit **Create** action in the fixed header to the right of the title, reachable while the form scrolls; back, scrim, or swipe dismissal abandons a new collection's draft. Editing an existing collection has no Save action: the fields the user edits (title, description, icon/symbol, color) autosave 500 ms after input pauses and immediately when the sheet closes, with saving/saved/failure feedback and Retry below the description. Unedited fields follow the stored row; an edited field keeps the user value until a write of its latest edit succeeds, and each write updates only edited fields, so another editor's change to any other field is never overwritten. Edited fields survive rotation and process recreation and are written once the row loads. A blank title stays in the editor as a recoverable draft with an inline error and is never written, so Room keeps the last valid title. Draft fields and delete confirmation survive state restoration. All editing controls wait for the initial row to load, so early decoration input cannot replace existing fields. Create is guarded while pending, failures retain the draft, and confirmed deletion cancels any pending autosave and leaves bookmarks intact. Sheet observers are scoped to the sheet lifetime.

Editor load failures show a load-specific message and Retry. Retrying restarts the row observer, preserves any restored draft, and keeps editing and writes disabled until the read succeeds. Repeated retry requests cannot start overlapping observers.

Titles are trimmed, required, and limited to 40 extended grapheme clusters. Descriptions are optional, limited to 100 clusters and two logical lines; additional line breaks become spaces. Android ICU BreakIterator preserves compound emoji, flags, skin tones, and combining marks. Custom symbol input keeps the last trimmed grapheme cluster and overrides the preset icon while present. Duplicate titles are allowed.

Preset IDs are `folder`, `schedule`, `star`, `work`, `code`, `lightbulb`, `palette`, and `favorite`. The theme palette has eight colors in fixed index order: cyan, sky blue, indigo, lavender, rose, coral, amber, and green. Default preset is `folder`, default color index is 0; repository writes reject unknown presets and indices outside 0 through 7.

## Bookmark assignment

The detail toolbar's Collection star opens Choose collections. At least one saved membership fills the star with a yellow/gold accent selected for at least 3:1 contrast against the toolbar background; no memberships use the outline icon. Room membership changes update this state reactively, including deletion of the final collection. The selection sheet has neither Save nor Cancel. Each checkbox change is saved when it is made as a single atomic add or remove; the row is disabled until that write finishes. Closing (back, scrim, swipe, or accessibility dismissal) only ends the interaction and runs the standard slide-down hide animation before the parent removes it. A failed change reverts that checkbox to the stored membership and shows an error with Retry, which re-applies the change. Assignment does not save or change bookmark notes, tags, or Like.

The selection sheet always displays a **New collection** action with a leading `+` icon above the existing collection choices, both when collections exist and in the empty state (below the empty-state prompt). Tapping **New collection** animates the selection sheet closed before presenting the creation sheet, so two bottom sheets never stack. Back during that closing animation cancels the switch: the selection sheet reopens and the creation sheet never appears. In the creation sheet, **Create** atomically inserts the new collection and assigns it to the originating bookmark in one Room transaction bound by stable bookmark and collection UUIDs (including when collection titles are duplicated), while preserving all existing memberships. When creation succeeds, the creation sheet animates closed and the selection sheet reopens with the newly created collection automatically checked, scrolled into view, and focused. If creation or assignment fails, the transaction rolls back completely without leaving an orphan collection or partial membership, retains the creation draft, and offers retry (via both the header **Create** action and an inline **Retry** button) using the same collection UUID without duplicate creation; if the originating bookmark was deleted or moved to Trash, creation stops without creating an orphan collection. Cancelling or dismissing the creation sheet (Back, scrim, or swipe) animates it closed and returns to the selection sheet without creating or assigning anything and without losing existing memberships, unresolved toggle failures, or scroll position.

Deleted collections disappear from the selector; a concurrently missing write target never produces a partial save. A load error offers retry, and a write error keeps the selector open. No navigation away to the Collection library, additional card action menu, bulk assignment, synchronization, or collection export/import is introduced.

Closing after a membership read failure leaves stored memberships untouched and uses the same slide-down animation and completion callback. Retry remains available until closing begins.

The editor and selection sheets expose inline errors through polite accessibility live regions. The title validation and selection error regions stay mounted before their messages appear. The title field reserves supporting text space only while its validation error is visible.
