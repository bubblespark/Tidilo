# Library Navigation

Status: Implemented.

## Intent and scope

Make Library the only root screen. Replace the floating navigation bar with a completely dismissible Material 3 Expressive modal rail. Keep existing bookmark storage, filters, search, direct ingestion, manual AI review, RSS behavior, themes, and localization.

Preserve the current theme foundation, including the fixed Modern palettes and raised Library/Search title styles. Removed navigation and Import overview components do not need their former text decoration restored.

## Approaches

- Selected: `ModalWideNavigationRail` with `hideOnCollapse = true`. It preserves the full Library width while closed and overlays content while open.
- Considered: `ModalNavigationDrawer`, which provides the desired interaction but is superseded by the expanded rail in Expressive guidance.
- Rejected for this phone layout: a persistent collapsed rail. Its icon column reduces the width available to the existing two-column bookmark grid.

## Library and rail

- Library alone exposes the rail through a top-left menu icon. Preserve the existing title, subtitle, header styling, and title interaction. Its only top-right action is the existing dashboard/gear display-mode selector. The menu glyph explicitly uses the header foreground color, and the display-mode popup anchors to its own button without the former two-action offset.
- The bottom-right Library shortcut trigger is a fixed 56dp circular control with a 28dp orbit glyph. It remains in place during scrolling and becomes Close while expanded. The four circular outer shortcuts are Collection, RSS, Domain, and Newest first from left to top (150dp radius, 180/210/240/270 degrees). Circular Search sits on the inner 225-degree diagonal at 73dp. All targets retain 56dp diameter. Placement is physical bottom-right with 24dp margins and independent system/cutout insets, including RTL. Scrolling content retains safe bottom insets plus 104dp clearance. Background card count does not affect the fan.
- Tap the trigger to open, then independently activate an item. Swiping from the trigger beyond platform movement slop opens immediately and keeps the original pointer until release. There is no long-press timer. Release over a circular item commits exactly once; crossings only update feedback. Search is navigation, not a filter, and has no selected state. Same-filter activation preserves the current drill-down; changing filters uses existing clearing behavior.
- Tap Close/outside, or press Back/Escape, to dismiss without underlying navigation. Continuous selection cancels on release over Close or a gap. Pointer cancellation, extra pointers, pause, window focus loss, rotation, and invalid geometry cancel; a late release cannot execute or reopen. Summary Peek and the collection editor hide the action.
- Use a same-window scaffold overlay after the header, with a 65% scrim blocking background touch and background header/body accessibility actions suppressed while open. The persistent trigger owns physical tap/swipe input and balanced press feedback; item controls retain independent semantic/keyboard activation. Targets use circular hit tests, including bounding-square corners. The trigger and Search use PRIMARY_ACTION, filters use FILTER_ACTION, with component-local CircleShape and shared screen-backdrop blur/fallback.
- A changed target supplies a highlight, one animated localized name away from the finger and other controls (above-left, above the fan, or beside it in a short window), and an entry haptic. Opening supplies one haptic; stationary samples do not repeat it. Icons do not enlarge. Controls travel from the trigger along the fan and retract over 230ms (cubic-bezier .2/.8/.2/1), with .65-to-1 artwork scale and a 140ms fade. Circular 56dp touch wrappers move with their artwork centers; Close wins overlaps, followed by reverse drawing order. Outgoing controls stop accepting input immediately. Reversing midway continues from the current position. Only the current filter is selected.
- Accessible controls are ordered Close, Search, Collection, RSS, Domain, Newest first. Opening focuses the persistent trigger; Tab/Shift+Tab cycle within the menu; arrow/D-pad focus cannot leave it for obscured controls. Close, Escape, Back, and active cancellation restore trigger input focus, including after touch dismissal. Window or inset changes while the menu is already closed do not request trigger focus. Screen-reader focus requires separate service verification. Menu state is ephemeral and never restored after recreation.
- The rail header contains Tidilo at the left and the existing `ic_notifications` action at the right. Only this header remains fixed while rail content scrolls.
- Scrollable content order: Search; Trash; the non-clickable Filters heading; Newest first; Domain; RSS; Collection; Manual Import; Settings. All entries except the section heading have an icon and label. The active filter is selected.
- Manual Import and Settings sit at the bottom of the scroll content, in that order. On tall screens, flexible space places them near the bottom. On short screens or large fonts, they scroll with the content; they are not a pinned footer.
- Empty Library and empty drill-down views (`EmptyLibraryMessage`) explain that pages can be saved directly or shared to Tidilo from a browser's share menu, and expose a **Save URL** primary button (`48dp` minimum touch height inside a vertically scrollable container respecting `contentPadding` clearance) that opens the existing `ImportUrlDialog`. When bookmarks are present, `Manual Import` remains in the navigation rail while the header and radial shortcut menu remain unchanged.
- Selecting a filter changes Library's existing filter state and closes the rail. Preserve existing domain/feed/collection drill-down behavior. No expandable subgroups are requested in this revision.
- Domain, RSS, and Collection overviews expose the Library menu; their drill-downs replace that icon with Up in the same persistent 48dp button, with 4dp trailing padding. Up clears the selected group and returns to its overview, where Menu opens the rail again. Only the glyph crossfades (220ms, EaseInOutCubic); button geometry and title position remain fixed. Click handling and the single accessible description follow the current hierarchy immediately, including during interrupted transitions. The outgoing and incoming glyphs are decorative. The only right-side action remains display mode.
- Opening the notification action or another destination closes the rail. Dismissal returns to the same Library. Back first dismisses an open rail.

## Secondary destinations

- Search, Trash, Notification, Manual Import, and Settings are children of Library. They have Back navigation and do not expose the rail or floating shortcut trigger. Existing deeper Settings pages remain nested under Settings.
- Trash is immediately below Search in the rail. Its text-only rows have no tap action; trailing Restore/Delete actions require confirmation, and active URL duplicates disable Restore. See [Trash](trash.md).
- Search retains its input, history, tag selection, results, and detail navigation. Opening Search from the inner Library Search shortcut or Navigation Rail, or returning to Search from Tag Selection, automatically focuses the search input and requests the software keyboard (IME). Opening Bookmark Detail explicitly clears Search focus and hides IME. Returning to Search preserves its scroll position without auto-focusing. Returning to Library restores its filter and scroll position.
- Manual Import opens a dialog over Library. A valid bare domain previews its resolved HTTPS address. Paste fills the URL field, and the URL keyboard's Go action uses the same validation and submission guard as Import.
- The dialog shows labeled indeterminate progress and blocks background interaction, Back, and outside dismissal during a manual save or retry. It keeps the URL and outcome across Activity recreation. After process termination, any restored draft is editable and startup recovery handles persisted tasks. A pending notification destination opens after the result is dismissed and Library is available.
- A save or a saved duplicate offers **Open saved page**, which opens Bookmark Detail for collection assignment. A failure with a stored task offers Retry for that exact task. Other failures return to editable input with the URL filled in.
- Direct acquisition has a 30-second deadline, including time waiting for an acquisition slot. Up to four direct acquisitions can run concurrently. A deadline cancels the Android HTTP request and makes its acquisition slot available for the next request. A late response cannot advance to bookmark persistence.
- Notification has a Back button, title, top-right **Clear history** action, and two sections. **Needs attention** lists retryable import ERROR tasks (including article HTTP failures) and RSS XML acquisition errors (including feed HTTP failures), with the note that they stay until retried or deleted. **History** lists saved notification history below it. Each section is newest first and is hidden, header included, when empty; the empty-state text appears only when both are empty. Section titles are accessibility headings. No tabs or Import groups.
- Each row displays its creation date and time to second precision in smaller secondary text below the main content. Use `yyyy/MM/dd HH:mm:ss` in the device's current time zone. Use notification.createdAt for history, task.createdAt for import failures, and the persisted failed-attempt timestamp for RSS XML failures. Never substitute the time the screen was opened. Preserve notification content and URL wrapping.
- Needs attention rows show, in order: a status label (page could not be saved, or feed turned off), the title, a localized explanation with a next step, the original diagnostic, the URL, the timestamp, and actions. The explanation is derived from the stored diagnostic without changing it: HTTP 500/502/503/504, 429, 401/403, 404/410 and other HTTP codes, network failures (host resolution, connection, timeout), secure-connection failures, missing article content, and on-device save failures each have their own text; anything else gets an honest unknown-cause fallback. RSS XML rows add that Retry turns the feed back on. The diagnostic preview is limited to two lines; when it is truncated, a Show details/Hide details toggle (with expanded/collapsed state) reveals the full, selectable text, and the expanded state survives scrolling and recreation.
- Needs attention rows have a visible tonal Retry button and a trailing three-dot overflow button whose menu contains Delete. History rows never offer Retry. Preserve stable row identity while a menu is open. While a request for a row is in flight, its Retry, overflow, and Delete are disabled, and Retry shows progress with a Retrying state description; there is no success message, and failures are reported in a Snackbar.
- Delete removes the selected notification/error item. For import errors, use the existing error-task deletion path. For RSS XML errors, dismiss the selected error without deleting the RSS subscription, its bookmarks, or changing its enabled state. Retry the exact import task or RSS feed, using their IDs rather than URL matching. Retry of XML acquisition must explicitly recover the disabled subscription through the existing scheduling/network policy; a repeated HTTP failure produces an actionable row again.
- Clear history semantics: clear saved notification history and its unread state, but preserve unresolved tasks and their retry actions. No confirmation is shown. Disable Clear history when no saved history exists, including when only Needs attention rows remain. Opening Notification retains the existing mark-as-read behavior. Clear history does not silently discard unresolved error tasks.
- Reuse stable notification, task and RSS feed IDs; do not associate retries by URL. A successful retry removes the live error row; a repeated failure remains retryable. Retry uses the current repository/RSS behavior and does not introduce automatic AI analysis.
- History rows display known stored messages (library duplicate, queue duplicate, RSS promotion) as localized text without changing stored values; other messages appear as stored. Library-duplicate and RSS-promotion rows offer **Open saved page**, using the stored bookmark ID or, for older entries without one, resolving by URL. The action verifies that the bookmark is active and reports when it is unavailable instead of navigating. Queue-duplicate and other history rows have no action, and history rows are not tappable as a whole.

## External entry points and constraints

- Normal launch starts at Library. The optional `TidiloApp(sharedUrl)` path imports once and returns to Library. `ShareReceiverActivity` keeps its current background-ingestion-and-finish behavior.
- Route old `import` notification intents to Notification on cold and warm start. New import error notices target Notification; manual AI review retains its existing in-screen feedback. Existing RSS completion and RSS settings destinations retain their behavior. OS channels remain separate from the in-app history.
- Use existing Compose Material 3, Navigation Compose, Room, Coroutines/Flow, and shared theme surfaces. No dependency, version, or application Gradle configuration changes. All content remains local; use English default resources and Japanese translations.
- The implementation uses focused navigation and notification components. Automated coverage includes route compatibility, error generations, storage completion/failure, draft restoration, fixed shortcut-trigger geometry, Library position restoration, and compact/large-font rail access.
