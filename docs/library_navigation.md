# Library Navigation

Status: Implemented.

## Intent and scope

The app has three top-level layers, Discover (home), Library (archive), and Search, switched by a floating toolbar with a Save FAB. Secondary destinations live in a completely dismissible Material 3 Expressive modal rail. Keep existing bookmark storage, filters, search, direct ingestion, manual AI review, RSS behavior, themes, and localization.

Preserve the current theme foundation, including the fixed Modern palettes and raised Library/Search title styles. Removed navigation and Import overview components do not need their former text decoration restored.

## Approaches

- Selected: `ModalWideNavigationRail` with `hideOnCollapse = true`. It preserves the full Library width while closed and overlays content while open.
- Considered: `ModalNavigationDrawer`, which provides the desired interaction but is superseded by the expanded rail in Expressive guidance.
- Rejected for this phone layout: a persistent collapsed rail. Its icon column reduces the width available to the existing two-column bookmark grid.

## Top-level layers and floating toolbar

- **Start layer & switching**: The graph starts at `Screen.Discover` (`"discover"`). `TopLevelDestination` maps `Discover`, `Library`, and `Search` to an app-level `TidiloFloatingNavigation` (`HorizontalFloatingToolbar` + trailing `+` Save FAB) positioned bottom-center with system/cutout insets plus `16.dp` bottom offset. Top-level switches use a vertical fade-through transition (`220ms` fade + `14.dp` spring rise) while keeping the toolbar stationary above `NavHost` with an app-level Haze backdrop sampling active screen bodies.
- **Save FAB**: The trailing `56.dp` Save FAB opens `ImportUrlDialog` from any top-level route. Library and Search reserve `HeaderDefaults.FloatingNavigationClearance` (`96.dp`) of bottom content clearance so results clear the toolbar when the IME is closed.
- **Back behavior**: Pressing Back on `Library` or `Search` returns to `Discover` before exiting. Inside a Library drill-down (Domain / RSS / Collection), Back clears the drill-down first, and a second Back returns to `Discover`.
- **Visibility & hiding**: The floating toolbar hides on downward scroll and restores on upward scroll or pull-down at top across top-level routes, hides while the software keyboard (IME) is open or the navigation rail is expanded, and is omitted on non-top-level routes (Bookmark Detail, AI Review, Settings, Notifications, Trash, Tag Selection).
- **Discover layer**: The home shows the rediscovery shelves described in [ui_discover.md](ui_discover.md). Card taps open Bookmark Detail; entity taps (Rising, Your map, Connections) open Search with the entity selected; Save URL and "How to save" open Manual Import.
- **Library layer**: Library shows the archive layer described in [Library UI §9](ui_library.md#9-library-layer): title **Library** with the per-tab count, a connected Newest / Domain / RSS / Collection button group under the title row, a single Grid/List toggle, 1.91:1 plate cards, and per-tab empty states that explain direct saving and sharing to Tidilo and offer **Save URL** (opens `ImportUrlDialog`).
- **RSS Settings from Library**: The RSS empty state's **Add feed** / **RSS settings** button opens `settings_rss` directly from Library. Back returns to Library, not Settings. This is the one deeper Settings page reachable outside Settings.

## Rail and Library header

- Discover and Library expose the rail through a top-left menu icon. Library preserves its title, subtitle, header styling, and title interaction; its only top-right action is the Grid/List toggle (Newest and drill-downs only). The menu glyph explicitly uses the header foreground color.
- The rail header contains Tidilo at the left and the existing `ic_notifications` action at the right. Only this header remains fixed while rail content scrolls.
- Scrollable content order: Trash; Settings. Search and Manual Import live on the floating toolbar and FAB, and the Library layer's button group replaces filter entries. Settings sits at the bottom of the scroll content: on tall screens, flexible space places it near the bottom; on short screens or large fonts, it scrolls with the content and is not a pinned footer.
- Domain, RSS, and Collection overviews expose the menu; their drill-downs replace that icon with Up in the same persistent 48dp button, with 4dp trailing padding. Up clears the selected group and returns to its overview, where Menu opens the rail again. Only the glyph crossfades (220ms, EaseInOutCubic); button geometry and title position remain fixed. Click handling and the single accessible description follow the current hierarchy immediately, including during interrupted transitions. The outgoing and incoming glyphs are decorative.
- Opening the notification action or another destination closes the rail. Dismissal returns to the same layer. Back first dismisses an open rail.

## Secondary destinations

- Trash, Notification, and Settings are children of the top-level layers; they have Back navigation and do not expose the rail or the floating toolbar. Search is a top-level layer hosting the floating toolbar when the IME is hidden. Existing deeper Settings pages remain nested under Settings.
- Trash is the first rail entry. Its text-only rows have no tap action; trailing Restore/Delete actions require confirmation, and active URL duplicates disable Restore. See [Trash](trash.md).
- Search retains its input, history, tag selection, results, and detail navigation. Opening Search from the floating toolbar, or returning to Search from Tag Selection, automatically focuses the search input and requests the software keyboard (IME). Opening Bookmark Detail explicitly clears Search focus and hides IME. Returning to Search preserves its scroll position without auto-focusing. Returning to Library restores its filter and scroll position. A long-press on a Search grid card opens the Peek sheet (Like, Add to collection; [Library UI §9](ui_library.md#9-library-layer)).
- Manual Import opens a dialog over the current top-level layer. A valid bare domain previews its resolved HTTPS address. Paste fills the URL field, and the URL keyboard's Go action uses the same validation and submission guard as Import.
- The dialog shows labeled indeterminate progress and blocks background interaction, Back, and outside dismissal during a manual save or retry. It keeps the URL and outcome across Activity recreation. After process termination, any restored draft is editable and startup recovery handles persisted tasks. A pending notification destination opens after the result is dismissed and a top-level layer is available.
- A save or a saved duplicate offers **Open saved page**, which opens Bookmark Detail for collection assignment. A failure with a stored task offers Retry for that exact task. Other failures return to editable input with the URL filled in.
- Direct acquisition has a 30-second deadline, including time waiting for an acquisition slot. Up to four direct acquisitions can run concurrently. A deadline cancels the Android HTTP request and makes its acquisition slot available for the next request. A late response cannot advance to bookmark persistence.
- Notification has a Back button, title, top-right **Clear history** action, and two sections. **Needs attention** lists retryable import ERROR tasks (including article HTTP failures) and RSS XML acquisition errors (including feed HTTP failures), with the note that they stay until retried or deleted. **History** lists saved notification history below it. Each section is newest first and is hidden, header included, when empty; the empty-state text appears only when both are empty. Section titles are accessibility headings. No tabs or Import groups.
- Each row displays its creation date and time to second precision in smaller secondary text below the main content. Use `yyyy/MM/dd HH:mm:ss` in the device's current time zone. Use notification.createdAt for history, task.createdAt for import failures, and the persisted failed-attempt timestamp for RSS XML failures. Never substitute the time the screen was opened. Preserve notification content and URL wrapping.
- Needs attention rows show, in order: a status label (page could not be saved, or feed turned off), the title, a localized explanation with a next step, the original diagnostic, the URL, the timestamp, and actions. The explanation is derived from the stored diagnostic without changing it: HTTP 500/502/503/504, 429, 401/403, 404/410 and other HTTP codes, network failures (host resolution, connection, timeout), secure-connection failures, missing article content, and on-device save failures each have their own text; anything else gets an honest unknown-cause fallback. RSS XML rows add that Retry turns the feed back on. The diagnostic preview is limited to two lines; when it is truncated, a Show details/Hide details toggle (with expanded/collapsed state) reveals the full, selectable text, and the expanded state survives scrolling and recreation.
- Needs attention rows have a visible tonal Retry button and a trailing three-dot overflow button whose menu contains Delete. History rows never offer Retry. Preserve stable row identity while a menu is open. While a request for a row is in flight, its Retry, overflow, and Delete are disabled, and Retry shows progress with a Retrying state description; there is no success message, and failures are reported in a Snackbar.
- Delete removes the selected notification/error item. For import errors, use the existing error-task deletion path. For RSS XML errors, dismiss the selected error without deleting the RSS subscription, its bookmarks, or changing its enabled state. Retry the exact import task or RSS feed, using their IDs rather than URL matching. Retry of XML acquisition must explicitly recover the disabled subscription through the existing scheduling/network policy; a repeated HTTP failure produces an actionable row again.
- Clear history semantics: clear saved notification history and its unread state, but preserve unresolved tasks and their retry actions. No confirmation is shown. Disable Clear history when no saved history exists, including when only Needs attention rows remain. Opening Notification retains the existing mark-as-read behavior. Clear history does not silently discard unresolved error tasks.
- Reuse stable notification, task and RSS feed IDs; do not associate retries by URL. A successful retry removes the live error row; a repeated failure remains retryable. Retry uses the current repository/RSS behavior and does not introduce automatic AI analysis.
- History rows display known stored messages (library duplicate, queue duplicate, RSS promotion) as localized text without changing stored values; other messages appear as stored. Library-duplicate and RSS-promotion rows offer **Open saved page**, using the stored bookmark ID or, for older entries without one, resolving by URL. The action verifies that the bookmark is active and reports when it is unavailable instead of navigating. Queue-duplicate and other history rows have no action, and history rows are not tappable as a whole.

## External entry points and constraints

- Normal launch starts at Discover. The optional `TidiloApp(sharedUrl)` path imports once and switches to Library. `ShareReceiverActivity` keeps its current background-ingestion-and-finish behavior.
- Route old `import` notification intents to Notification on cold and warm start. New import error notices target Notification; manual AI review retains its existing in-screen feedback. Existing RSS completion and RSS settings destinations retain their behavior. OS channels remain separate from the in-app history.
- Use existing Compose Material 3 (BOM-managed `1.5.0` via Compose BOM `2026.11.01`), Navigation Compose, Room, Coroutines/Flow, and shared theme surfaces. All content remains local; use English default resources and Japanese translations.
- The implementation uses focused navigation and notification components. Automated coverage includes route compatibility, error generations, storage completion/failure, draft restoration, Library position restoration, and compact/large-font rail access.
